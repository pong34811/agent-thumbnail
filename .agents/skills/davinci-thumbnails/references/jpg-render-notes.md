# บันทึกการทำปกเป็น JPG นอก Canva

บทเรียนจากงาน 【DEBUT STREAM】AOMI-MAMA (26 กันยายน 2026, 8 Timeline × แนวนอน + Shorts) ใช้เมื่อผู้ใช้ขอไฟล์ภาพหรือเมื่อ Canva ใช้ไม่ได้ เอนจินที่ใช้จริงอยู่ใน `src/engine/` และคำสั่งอยู่ใน `cli/` (สคริปต์รุ่นเก่าถูกลบแล้ว ดู git history)

## ยืนยันขอบเขตก่อนเริ่ม

- path โปรเจกต์ที่ผู้ใช้พิมพ์, โฟลเดอร์ภาพโมเดล และโปรเจกต์ที่เปิดอยู่ใน Resolve อาจเป็นคนละช่อง ถ้าไม่ตรงกันให้ถามหนึ่งคำถามพร้อมตัวเลือกก่อนลงมือ อย่าใส่โมเดลของอีกช่องลงบนคลิปของช่องหนึ่งเอง
- Timeline ทั้งหมดเป็น 1920×1080 แต่ผู้ใช้ขอกฎ Shorts ด้วย: ถามว่าจะเอาแนวนอน, Shorts หรือทั้งคู่ แล้วตั้งชื่อ Shorts เป็น `<ชื่อ Timeline>-short.jpg`

## อ่าน Timeline จาก DaVinci Resolve

- อ่าน track/item/subtitle ผ่าน API แบบอ่านอย่างเดียวได้เร็ว (`GetItemListInTrack`, `GetSourceStartFrame`, `GetMediaPoolItem().GetClipProperty("File Path")`)
- **อย่าเปิด Fusion comp ของ Text+ ผ่าน API ทีละ item** (`GetFusionCompByIndex` / `GetToolList`) ใน Resolve 21.1 ทำให้โปรแกรมค้างจนปิดไป ถ้าจำเป็นต้องเปิดใหม่ ให้โหลดโปรเจกต์เดิมกลับและแจ้งผู้ใช้
- ข้อความ Text+ อ่านจากไฟล์ backup `.drp` แทนได้: `SeqContainer/*.xml` → `<CompositionBA>` (hex) → ข้าม 4 ไบต์แรก → zlib → หา `\x78\xda` หลัง `Compressed = true` → zlib อีกชั้น → `Text = Input { Value = "..." }` ลำดับ comp ตรงกับลำดับ item บน track (ดู `extract_textplus.py`)
- ถ้า .drp เก่ากว่าการตัดต่อล่าสุด ให้เทียบจำนวน Text+ กับ Timeline ปัจจุบัน และดูเฟรมที่ render มาเทียบคำอย่างน้อยบางจุด

## เลือกข้อความ

- คำบน subtitle บางบรรทัดเป็น **แชทของคนดูที่สตรีมเมอร์อ่านออกเสียง** ตรวจกับ LIVE CHAT ในเฟรมก่อนเขียนเหมือนเป็นคำพูดของเธอ ถ้าชื่อ Timeline ของผู้ใช้เลือกกรอบนั้นเอง ให้ใช้ได้แต่ต้องแจ้งในรายงาน
- hook สีแดงควรเป็นมุก/เหตุการณ์ที่แรงที่สุดในคลิป (เช่น "จ้วงแทงคนจากข้างหลัง") ส่วนข้อความขาวให้บริบท ไม่ใช่ทวนชื่อ Timeline ซ้ำ
- แก้คำพิมพ์ผิดของ subtitle ได้ (จวง→จ้วง, เนี้ย→เนี่ย) แต่ชื่อไฟล์ต้องใช้ชื่อ Timeline ตามเดิมทุกตัวอักษร รวมคำผิดในชื่อ

## วางข้อความไทยด้วย Pillow

- ใช้ `ImageFont.Layout.RAQM` เสมอ (ต้องมี libraqm) ไม่อย่างนั้นสระบน/วรรณยุกต์จะวางผิด
- Mitr มี line height ราว 1.6 em จึงห่างเกิน ให้ซ้อนบรรทัดตาม ink bbox จริงของแต่ละบรรทัด (รวม stroke) แล้วเว้นช่องประมาณ 0.06 em
- ปก Shorts ให้จัดกึ่งกลางด้วย ink ที่มองเห็น ไม่ใช่ advance ของ glyph เพราะสระ/วรรณยุกต์ที่เลื่อนแล้วทำให้เยื้องได้หลายพิกเซล
- ขอบดำหนา (~0.12 em) ทำให้สระบน/วรรณยุกต์ **ติดหาง ป ฝ ฟ** (เช่น ไลฟ์, ฝัง) และ **ติดหัว ไ ใ โ** ที่ตามมา (เช่น แต่ไม่ได้) ให้แยกวาดเครื่องหมายนั้น แล้วเลื่อนซ้ายเท่าที่จำเป็นให้ fill ห่างหมึกที่สูงเกินเส้น x-height อย่างน้อย 0.05 em ถ้า Mitr วางห่างพอแล้ว (ปิ, เป้า) ห้ามขยับ และถ้าฟอนต์ออกแบบให้ติดฐานเอง (สี, สิ่) ให้คงไว้ ดู `line_masks()` ใน `build_covers.py`
- เลข 0 ของ Mitr Bold มีขีดทับเป็นดีไซน์และไม่มี glyph ทางเลือก ให้แจ้งผู้ใช้แทนการเปลี่ยนฟอนต์เอง

## พื้นหลัง

- ไลฟ์คุย/เดบิวต์มักมีสไลด์ตัวอักษรใหญ่ (Profile, Story, Goals) ให้ใช้เฟรมหรือภาพนิ่งจาก Timeline นั้น แต่เบลอราว 46 px (แนวนอน) / 60 px (Shorts) และลดความสว่างเหลือราว 0.5 จนไม่มีคำไหนอ่านออกที่ขนาด 50%
- ภาพที่แทรกบน Timeline (เช่น ภาพเกมที่กำลังพูดถึง) ใช้เป็นพื้นหลังได้และช่วยให้ปกคู่ที่ใช้สไลด์เดียวกันไม่ซ้ำหน้าตา
- ตรวจเงาของตัวละครในฉาก (Live2D ในเฟรม, สติกเกอร์บนสไลด์) ที่อาจโผล่ข้างโมเดลจริง

## โมเดล

- ภาพ VTube Studio 4K ให้ครอปแค่อก (ให้เห็นคอเสื้อ ไม่จบที่คอเปล่า) ใช้ขอบล่างภาพเป็นขอบล่างปก และลบชิ้นผม/alpha เล็ก ๆ ที่ขาดติดขอบครอป มิฉะนั้นจะได้ขอบขาวเป็นเกาะแยก
- เวลาทำขอบขาวและเงา ให้ pad layer รอบด้านให้พอกับรัศมีเบลอ ไม่อย่างนั้นเงาจะถูกตัดเป็นเส้นตรงเหนือหู
- สติกเกอร์ชิบิ 600×503 นุ่มลงเมื่อขยายเกิน ~1.5 เท่า ให้แจ้งและขอไฟล์ความละเอียดสูงถ้ามี
- เทียบสีหน้ากับเฟรมจริง: เรื่อง "ตกใจจนปิดไลฟ์หนี" ที่เล่าแบบหัวเราะควรใช้หน้าหัวเราะ ไม่ใช่สติกเกอร์ร้องไห้ และอย่าใช้ภาพเดียวกันกับสองคลิปที่อารมณ์ต่างกัน
- ระวัง prop ที่ขัดกับคำพูด (เช่น ถือเครื่องเกมพกพาในคลิปที่บอกว่าชอบเล่นบนคอม)

## บทเรียนจากงานไฮไลท์เกม Armigon (28 กันยายน 2026, 16 Timeline × แนวนอน + Shorts)

สคริปต์ตัวอย่างอยู่ใน `scripts/build_armigon_covers_v3.py` และ `scripts/armigon_graphics_overlay.py` ของ skill นี้:

1. **ฉากหลังเกมเพลย์ต้องไม่เบลอ (กฎ 1 วินาที):**
   - ปกคลิปเกมต่างจากสไลด์พูดคุยเดบิวต์ ห้ามเบลอฉากหลังจนจำเกมไม่ได้ ให้ใช้ **0 px (ไม่เบลอเลย)** ความสว่างประมาณ `0.90` (มืดลงเพียง 10%) และสี `1.12`, คอนทราสต์ `1.08`
   - ป้องกันไม่ให้ฉากหลังแย่งสายตาด้วย **Backdrop Gradient Mask** เฉพาะโซนข้อความด้านซ้าย (ความเข้ม 50–65% ที่ขอบซ้าย ค่อย ๆ จางหายไปที่ `x ≈ 980`) แทนการเบลอทั้งภาพ
2. **ยกระดับข้อความขึ้นกึ่งกลางซ้าย (Center-Left Elevation):**
   - อย่าให้ข้อความกองอยู่ที่มุมซ้ายล่างสุด (`y > 700`) เพราะจะโดนแถบเวลา Scrubber ของ YouTube บดบัง และทำให้ภาพดูหนักล่าง
   - จัดข้อความให้อยู่ที่ `y ≈ 380–520` (กึ่งกลางแนวตั้งของฝั่งซ้าย)
   - ป้องกันการลดขนาดฟอนต์โดยไม่จำเป็น: หากข้อความมีหลายบรรทัด ให้วัดความกว้างแยกแต่ละบรรทัด (`fit_lines_font`) เพื่อให้ฟอนต์คงขนาดใหญ่ที่สุด (~150–165 px) ไม่ใช่หดฟอนต์ทั้งประโยคยาวลงไปที่ 80 px
3. **Graphic Storytelling (วงกลมพู่กันแดง + เครื่องหมายอารมณ์):**
   - **วงกลมพู่กันแดง (`#EC1C24`):** วาดเส้น Loop ที่เหลื่อมกันเล็กน้อยแบบ Hand-drawn ด้วย Pillow พร้อมเส้นขอบดำหนาและ Drop shadow ล้อมจุดเกิดเหตุในเกม
   - **เครื่องหมาย `!` / `?` สไตล์อนิเมะ:** ขอบดำหนา 14 px พร้อม Drop shadow เอียง 10–12° วางลอยข้างหมวก/หูตัวละคร
4. **กระจายใช้โมเดลตามเนื้อหาจริง (Avatar Matrix):**
   - แมตช์อารมณ์จากคลังโมเดล (`cry`, `angry`, `hello`, `great`, `sadistic`, `adore`) ให้ตรงกับจุดพีกของคลิป เช่น ท่ากอดหัวใจกับคลิปวันเกิด, ท่าถือมีดยิ้มร้ายกับคลิปตามล่าหรือแกล้งเพื่อน, ท่า thumbs-up กับคลิปทำสำเร็จ

## ตรวจก่อนส่ง

รันตัวตรวจเชิงกลทุกครั้ง (`verify_covers.py` หรือ pytest suite): ชื่อไฟล์ครบตามชื่อ Timeline, ขนาด/ฟอร์แมต, ข้อความอยู่ในขอบปลอดภัย, ไม่ทับกรอบโมเดล, Shorts จัดกึ่งกลาง ±3 px และโมเดลอยู่ครึ่งล่าง, hook ใหญ่กว่าข้อความรอง แล้วดูภาพเต็มและย่อ 320×180 / 180×320 ด้วยตา งานนี้ต้องตรวจความสมดุลสายตาระหว่างข้อความ ตัวละคร และจุดเกิดเหตุในเกมให้กลมกลืนกัน
